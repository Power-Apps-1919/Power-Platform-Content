## Component documentation

## Business value
Make the state of a record, request, task, or process visible without requiring users to open it.

## Best for
- Approval and delivery stages.
- Active, inactive, pending, or error states.
- Lists and dashboards where space is limited.

## What to provide
- `StatusValue`: the current state.
- `StatusLabel`: an optional user-friendly label.
- `TooltipText`: supporting context.

## Getting started
Use `cmp-status-badge.yml` as a reference while creating or maintaining the equivalent component in a component library or approved source workflow; use a controlled set of status values, and make sure the meaning is still clear without relying only on colour.

## Using the component YAML safely

This download is a complete `ComponentDefinitions` source file. It is useful as a
versioned reference and for supported source-code workflows, but it should not be
treated as an ordinary control snippet.

### Recommended reusable approach: component library

For a component that will be used across apps, Microsoft recommends a Power Apps
component library:

1. Open [Power Apps](https://make.powerapps.com).
2. Open **Component libraries** from **More** or **Discover all**, then create or
   open a library.
3. Create or maintain the component in the library and test it on a library screen.
4. Save the library, add version notes, and select **Publish**.
5. In the Canvas App, select **Insert** or **+**, choose **Get more components**,
   and select the shared library.
6. Add the component and configure its input, output, action, or event properties.

Published library versions can be updated and reviewed by apps that use them. This
is the best option when several makers or apps need the same component.

### Use a component in an individual app

For reuse only within one app, you can create an app-local component in Power Apps
Studio:

1. Open the app and select **Tree view**.
2. Select the **Components** tab, then **New component**.
3. Add the controls and custom properties that define the component.
4. On a screen, use **Insert** → **Components** to add an instance.

App-local components can be reused on multiple screens in that app. Changes remain
within that app; they do not provide the cross-app versioning and update
notifications of a component library.

### Copy and paste supported control YAML

Power Apps Studio also has **View code** for an individual control. Microsoft
documents this workflow for YAML generated by Studio:

1. Open the Canvas App for editing.
2. In the tree view or on the canvas, right-click an individual control and select
   **View code**.
3. Select **Copy code**, or use `Ctrl+C`.
4. In the destination app, select a screen or suitable location in the tree view.
5. Use **Paste** or `Ctrl+V` to create the control. This can be another screen in
   the same app or a different canvas app.
6. Approve browser clipboard access if Power Apps asks for it.

Studio validates the pasted code. This workflow applies to YAML that Power Apps
generated for a selected control and its child controls. It does not mean that a
full `ComponentDefinitions` file can be pasted into any code-view window.

### Can this complete file be pasted directly?

Do not assume that copying the entire downloaded file and pasting it into Code view
will create this component. These files define a Canvas component and its
properties, while Code view is documented for selected controls. If Studio rejects
the paste, that is expected for an unsupported format or location.

Use the component-library workflow for shared components. The older feature for
importing and exporting components between canvas apps is retired and disabled by
default; Microsoft documents a temporary per-app exception under **Settings** →
**Upcoming features** → **Retired** where that option is still available. Prefer
component libraries instead. If your organisation uses a supported source-code,
unpacking, or ALM process, keep this YAML in source control and follow that process
to apply it.

## Best practices

- Test first in a development environment with sample data.
- Keep the component interface small and use clear property names and descriptions.
- Pass business data through documented input properties rather than hard-coding records.
- Use output, action, and event properties only when the host app needs them.
- Confirm connector permissions, licensing, accessibility, responsive layout, and colour contrast.
- Save component-library versions with meaningful notes and publish changes deliberately.
- Validate formulas and data schemas after every update.
- Do not place secrets, connection credentials, personal data, or production exports in source files or downloads.

## Source preview

```yaml
ComponentDefinitions:
  StatusBadge:
    DefinitionType: CanvasComponent
    CustomProperties:
      StatusValue:
        PropertyKind: Input
        DisplayName: Status Value
        Description: The status to display (e.g., "Active", "Inactive", "Pending", "Error").
        DataType: Text
        Default: ="Active"
      StatusLabel:
        PropertyKind: Input
        DisplayName: Status Label
        Description: Optional label to display instead of the status value.
        DataType: Text
        Default: =""
      TooltipText:
        PropertyKind: Input
        DisplayName: Tooltip Text
        Description: Tooltip text for additional information about the status.
        DataType: Text
        Default: =""
    Properties:
      Height: =40
      Width: =120
    Children:
      - BadgeContainer:
          Control: GroupContainer@1.3.0
          Variant: ManualLayout
          Properties:
            Height: =Parent.Height
            Width: =Parent.Width
            X: =0
            Y: =0
            Fill: |
             =Switch(
                Lower(StatusBadge.StatusValue),
                "active", RGBA(46, 204, 113, 1),
                "inactive", RGBA(149, 165, 166, 1),
                "pending", RGBA(241, 196, 15, 1),
                "error", RGBA(231, 76, 60, 1),
                RGBA(127, 140, 141, 1)
              )
            RadiusTopLeft: =20
            RadiusTopRight: =20
            RadiusBottomLeft: =20
            RadiusBottomRight: =20
          Children:
            - StatusIcon:
                Control: Classic/Icon@2.5.0
                Properties:
                  Icon: |
                    =Switch(
                      Lower(StatusBadge.StatusValue),
                      "active", Icon.CheckBadge,
                      "inactive", Icon.Blocked,
                      "pending", Icon.Clock,
                      "error", Icon.CancelBadge,
                      Icon.Information
                    )
                  Height: =24
                  Width: =24
                  X: =8
                  Y: =8
            - StatusTextLabel:
                Control: Label@1.0.0
                Properties:
                  Text: =If(!IsBlank(StatusBadge.StatusLabel), StatusBadge.StatusLabel, StatusBadge.StatusValue)
                  Color: =RGBA(255,255,255,1)
                  Font: =Font.'Open Sans'
                  FontWeight: =FontWeight.Bold
                  Size: =16
                  X: =40
                  Y: =8
                  Height: =24
                  Width: =Parent.Width-48
                  Tooltip: =StatusBadge.TooltipText
```
